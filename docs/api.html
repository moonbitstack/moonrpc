struct
struct ServerKeepalive

A server's keepalive policy (gRPC A8): time is how long an idle connection is left alone before the server pings it, timeout how long the PING may go unanswered before the connection is declared dead, min_ping_interval the shortest gap the server will tolerate between a peer's PINGs, and max_ping_strikes how many of those too-soon PINGs a peer gets before the connection is closed.

let
let server_keepalive : ServerKeepalive =

The policy gRPC core uses when a server sets none: two hours of idleness before a PING, twenty seconds to answer it, a PING no more often than every five minutes, and two strikes before the peer is told to calm down (ENHANCE_YOUR_CALM).

struct PingGuard

The guard a server keeps against a peer that pings it faster than the policy allows: a PING inside min_interval is a strike, and max_strikes of them end the connection. This is what stops a client from keeping a hundred thousand connections alive with a PING every millisecond.

fn

A guard that has seen no PING yet.

fn
fn PingGuard::observe(self : PingGuard, now : Int64) -> Bool

Record a PING at now and say whether the peer has struck out. The first PING of a connection is never a strike: last starts at the connection's own start.

fn
fn ServerKeepalive::ping_guard( self : ServerKeepalive, now~ : Int64 = 0L) -> PingGuard

The guard a policy implies, or None when the server takes no view on PING rate.

fn
fn is_binary_metadata(name : Bytes) -> Bool

True when a metadata key carries binary, which gRPC spells by suffixing the key with -bin.

fn
fn metadata_value_from_wire(name : Bytes, value : Bytes) -> Bytes

Decode a metadata value coming off the wire: base64 for a -bin key, verbatim otherwise. Padding is optional on the wire, and a peer may pad or not; anything outside the alphabet is skipped rather than rejected, which is what the gRPC spec asks a receiver to tolerate.

fn

Encode a metadata value for the wire: base64 for a -bin key, verbatim otherwise. The base64 form carries no = padding, as gRPC's own clients send it; the receiver accepts padded or unpadded alike (§6.1 of the gRPC HTTP/2 spec).

let
let max_message_size : Int32

The default cap on a single received gRPC message (4 MiB, matching gRPC's default MaxRecvMsgSize). A length prefix above this — including one whose 4 bytes decode to a negative Int because the high bit is set — is rejected rather than trusted, so a hostile prefix can neither slice out of bounds nor pin unbounded buffer.

let
let max_header_list_size : Int32

The cap on one accumulated header block (HEADERS plus its CONTINUATION frames). Without it a peer could stream endless non-final CONTINUATION frames and grow the buffer without bound (a CONTINUATION flood); 128 KiB is far above any real gRPC request's headers.

fn
fn encode_message(payload : Bytes, compressed~ : Bool = false) -> Bytes

Encode a payload as a gRPC *Length-Prefixed-Message*: a 1-byte compression flag, a 4-byte big-endian length, then the payload. This is the framing every gRPC transport shares (gRPC-Web over HTTP/1.1 and real gRPC over HTTP/2 alike).

fn
fn decode_message(data : Bytes) -> (Bool, Bytes)?

Decode one gRPC length-prefixed message from the front of data, returning (compressed, payload), or None if fewer than a full frame is present.

fn
fn message_len(data : BytesView, at~ : Int32 = 0) -> Int32?

The payload length of the length-prefixed message at at, or None when fewer than the five octets of a prefix are there. A prefix with its high bit set reads back negative, which is how a hostile length is told from a real one before anything is sliced on it. Every reader of this framing goes through here — there are five of them across the client, the server and the socket transport, and they have to agree.

fn
fn split_messages(data : Bytes) -> Array[Bytes]

Split a run of concatenated length-prefixed messages into their payloads, stopping at the first one that has not fully arrived.

fn
fn H2Server::goaway( self : H2Server, last_stream_id : Int32) -> Array[@http2.Frame]

Frames for a graceful shutdown: a GOAWAY announcing last_stream_id — the highest client stream the server will still process (RFC 7540 §6.8) — with NO_ERROR, so the peer opens no new streams while in-flight ones finish. The driver writes these before closing the connection. fn
fn H2Server::closing(self : H2Server) -> Bool

Whether a connection error has been reported. The GOAWAY carrying it came back from the feed that found it, so the driver writes that and then closes; the engine processes nothing more (RFC 9113 §5.4.1).

fn
fn H2Server::feed( self : H2Server, frame : @http2.Frame) -> Array[@http2.Frame]

Feed one decoded incoming frame to the engine, advancing all state and returning the frames to write back (SETTINGS ack, PING pong, WINDOW_UPDATE, and — as the request stream progresses — the framed gRPC response messages and trailers). A protocol fault comes back as the frames that report it rather than as a raise the driver can only discard: RST_STREAM for a stream error, and for a connection error a GOAWAY, after which closing is set and every later frame is ignored (RFC 9113 §5.4).

fn
fn H2Server::tick(self : H2Server) -> Array[@http2.Frame]

Expire every call whose deadline has passed, returning the frames that end them. The driver calls this on whatever schedule it keeps time on; the engine also checks the deadline whenever a stream advances, so a call that is making progress never needs a tick to be cut off.

fn
fn H2Server::active_streams(self : H2Server) -> Int32

One message's worth of reading and writing. reset points a protocol at the bytes to read and clears what it has written, so one object serves a whole connection: read a frame, write the reply, read the next frame. async fn GrpcServer::serve( self : GrpcServer, host~ : String = "127.0.0.1", port~ : Int32 = port, tls? : @tls.Server) -> Unit

Serve gRPC on host:port — h2c, or over TLS when tls is given, in which case every accepted connection must have settled on ALPN h2 — blocking in the accept loop until the running task is cancelled or graceful_stop drains the server. item
async fn GrpcServer::graceful_stop( self : GrpcServer, grace~ : Int32 = 10000) -> Unit

Stop serving without cutting anyone off: stop accepting new connections, let the calls that are already running finish, and send every connection a GOAWAY naming the last stream it opened, so clients know what was accepted and can reconnect elsewhere. Returns once the last connection is gone, or after grace milliseconds — a client that received the GOAWAY and then went quiet without closing cannot be waited on forever. serve returns on its own once the accept loop and the last driver are done, so the task running it ends without being cancelled; if the grace period ran out with connections still open, cancelling that task is what releases them.

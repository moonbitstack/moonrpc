An interface is not a convention;
it is a compiler-enforced contract.

moonrpc is a gRPC library for MoonBit. It runs the gRPC over HTTP/2 protocol itself — frames, flow control, HPACK — and splits the work into two pure engines that exchange frames in memory, with a native socket layer only where a socket is unavoidable.

$ moon add moonbitstack/moonrpc

Read the guide Run it in the browser

the engines never see a socket — they trade frames like any other value.

architecture

Two engines, one memory

The client engine and the server engine are pure functions: hand them an Array[@http2.Frame], get back the frames to send. Nothing about them is tied to a transport. Only src/net — the real TCP layer — is native. That single split is why the same library, unchanged, runs in a browser demo and on a server.

call kinds

Four shapes of a call

gRPC defines four call kinds. moonrpc implements all of them as the same frame machinery — only the number of messages each side sends differs.

unary

One in, one out

A single request, a single response. SayHello: one message in, one message out.

 server streaming

One in, many out

The server keeps the stream open and sends a sequence. Counter.Up ticks 1, 2, 3…

 client streaming

Many in, one out

The client streams a sequence, the server replies once. Sum.Add folds them.

 bidi streaming

Many in, many out

Both sides stream. Chat.Talk is a live conversation, interleaved.
what it carries

A complete gRPC stack

Everything here is implemented in the library, not deferred to a sidecar or proxy.

①

Real gRPC

Wire-compatible gRPC over HTTP/2 — no proxy, no envoy, no translation layer.

②

Self-built HTTP/2

RFC 9113 frames, streams and flow control implemented in MoonBit.

③

HPACK

RFC 7541 header compression, dynamic table included.

④

17-code Status

The gRPC Status, mapped from HTTP/2 and HTTP errors.

⑤

Metadata

Per-call request and response metadata, with the base64 key rules.

⑥

Health & Reflection

grpc.health.v1 and grpc.reflection.v1 built in — grpcurl works.

⑦

#rpc annotations

Derive handlers, registrars and descriptors straight from your types.

⑧

Retry & hedging

gRPC A6 policy, throttling and pushback around every call.

⑨

Load balancing

Connectivity state, balancers, DNS resolution and a channel pool.
